## Run procedure and manual QA

1. Record commit, scanner/rule-pack versions, workflow result, selected modules, geo and rollout controls. Use one geo per row above. If Consent needs a cross-geo comparison, add only the specific second run and record why. Tracking/Server results do not need redundant geo runs by default.
2. Before paid scans, confirm Browserless/Decodo budgets and access policies. Keep difficult-site escalation manual and opt-in. Save bounded evidence and the final canonical result for each attempt. Replay the completed bundle offline and compare every canonical export field.
3. Manually inspect every unexpected definitive failure, unexpected `not_detected`, generic first-party Server classification, access failure, consistency violation, and candidate/request truncation. Sample representative passes and each major inconclusive reason. Compare against captured browser/network facts, Page/epoch provenance, CMP state and module-specific completeness. Do not judge by an assumed site implementation.
4. Record each disagreement as confirmed scanner defect, changed site, access limitation, or unverified expectation. Fix deterministic defects and rerun the launch gate before expanding.

## Telemetry to record

Attempted/completed counts; access, proxy and challenge failure rates; overall pass/warning/fail/inconclusive; module inconclusive and reason-code distributions; candidate/request truncation rates; consistency violations; replay mismatches; first-party Server and generic candidate counts; PDP found rate; `view_item` pass/missing/inconclusive; CMP provider distribution; module and total duration distributions; evidence bundle size. Capture available external Decodo traffic and Browserless usage, then compute cost per successful and attempted audit. No new paid telemetry infrastructure is required for LN-06.

## Go/no-go before a 25–50 domain bulk canary

Require CI green on `npm run validate`, compiled browser smoke, and whitespace check. In the manually verified sample require **zero** known false definitive absence from incomplete observation, erased positive findings, functional/storefront APIs classified as first-party measurement, strict-duplicate Server failures, cookie/request-count escalation above `first_party_collection_detected`, live/replay canonical mismatches, unexplained consistency violations, access failures reported as missing implementation, raw correlation identifier leaks, and Server-specific active reload/probe regressions. Observe runtime and external cost first, then decide whether they are acceptable for 300–1,000 audits/month; do not set a cost threshold without measurement. An elevated truthful inconclusive rate is reviewed by reason and volume, not automatically treated as failure.

LN-06 changes canonical precedence, request-truncation and result-field consistency, so rule pack `2026.09.26.6` is required. Scanner version remains `2.1.0`. This runbook does not authorize or perform the canary or a deployment.
